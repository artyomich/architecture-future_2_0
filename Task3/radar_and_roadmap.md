### Технический радар и роадмап изменений для «Будущее 2.0»

Решение фокусируется на **реалистичной поэтапной реализации**, **чёткой привязке к бизнес-метрикам**, **управлении рисками** и **обеспечении соответствия регуляторным требованиям**.

---

## Часть 1: Технический радар

Технический радар классифицирует технологии по двум осям: **Квадранты** (области применения) и **Кольца** (степень готовности к использованию). Это позволяет командам принимать обоснованные решения о выборе стека.

---

## Часть 2: Роадмап изменений

Роадмап состоит из 4 фаз, каждая из которых решает специфичные бизнес-задачи и закладывает фундамент для последующих этапов.

### Общая стратегия:
*   **Фаза 1 (Месяцы 1-3):** Фундамент. Решение критичных проблем (масштабируемость, безопасность).
*   **Фаза 2 (Месяцы 4-6):** Скорость решений. Запуск портала самообслуживания.
*   **Фаза 3 (Месяцы 7-12):** Масштабирование. Независимое развитие доменов.
*   **Фаза 4 (Месяцы 13-18):** Оптимизация. Снижение затрат и подготовка к будущему росту.


### Детализация этапов

#### **Фаза 1: Фундамент и безопасность (Месяцы 1-3)**

| **Цель** | Создать стабильную, масштабируемую и безопасную основу для всех будущих изменений. |
| :--- | :--- |
| **Ключевые шаги** | **Ожидаемые результаты** | **Ответственные** | **Ресурсы** |
|---|---|---|---|
| Миграция в облако (Azure/AWS) | Снижение CapEx на 30%, готовность к масштабированию | DevOps, Архитекторы | Облачный бюджет, 5 инж. |
| Контейнеризация на K8s | Автоматическое масштабирование, изоляция сбоев | DevOps, Разработка | K8s-кластер, 4 инж. |
| Внедрение Kafka вместо Apache Camel | Асинхронная коммуникация, устранение бутылочного горлышка | Интеграция, Архитекторы | Kafka-кластер, 3 инж. |
| Настройка мониторинга (Prometheus/Grafana) | Проактивное обнаружение проблем, SLA 99.5% | SRE, DevOps | Инструменты мониторинга |

**Обоснование для бизнеса:**
*   **Скорость:** Позволяет быстро развертывать новые сервисы (дни → часы).
*   **Качество:** Повышает доступность и отказоустойчивость критичных систем.
*   **Снижение затрат:** Переход от CapEx к OpEx, оплата только за используемые ресурсы.
*   **Масштабирование:** Облачная инфраструктура легко масштабируется под нагрузку.

---

#### **Фаза 2: Портал самообслуживания (Месяцы 4-6)**

| **Цель** | Решить главную бизнес-проблему — медленную подготовку отчетов и зависимость от IT. |
| :--- | :--- |
| **Ключевые шаги** | **Ожидаемые результаты** | **Ответственные** | **Ресурсы** |
|---|---|---|---|
| Создание DWH и Data Lake | Централизованное хранилище для аналитики и сырых данных | Data Eng, Аналитики | DWH, 6 инж. |
| Создание OLAP кубов | Предрасчитанные агрегаты для сверхбыстрых отчетов | BI, Data Eng | OLAP-сервис, 3 инж. |
| Разработка портала (React) | Самообслуживание для бизнес-пользователей | Frontend, Product | Команда 8 чел. |
| Миграция данных из SQL Server | Обеспечение полноты данных в новой витрине | Data Eng, DBA | Инструменты миграции |

**Обоснование для бизнеса:**
*   **Скорость:** Отчеты формируются за секунды/минуты, а не часы.
*   **Качество:** Улучшенный UX, интерактивный анализ данных.
*   **Снижение затрат:** Снижение нагрузки на IT-отдел на 60%.
*   **Масштабирование:** Портал легко расширяется для новых типов отчетов и пользователей.

---

#### **Фаза 3: Независимые домены (Месяцы 7-12)**

| **Цель** | Обеспечить возможность параллельной и независимой разработки всех бизнес-направлений. |
| :--- | :--- |
| **Ключевые шаги** | **Ожидаемые результаты** | **Ответственные** | **Ресурсы** |
|---|---|---|---|
| Выделение медицинского домена | Изоляция и соответствие медицинским регуляторам (HIPAA) | Мед. команда, Архитекторы | 8 инж. |
| Выделение финтех-домена | Изоляция и соответствие финансовым регуляторам (PCI DSS) | Финтех команда, Архитекторы | 8 инж. |
| Выделение ИИ-домена | Независимое развитие ML-моделей | ИИ команда, DS | 6 инж. |
| Создание партнёрского домена | Быстрая интеграция новых партнёров (2 недели) | Интеграция, Архитекторы | 4 инж. |
| Внедрение API Gateway | Единая точка входа, централизованная безопасность | DevOps, Интеграция | 3 инж. |

**Обоснование для бизнеса:**
*   **Скорость:** Time-to-market сокращается с кварталов до недель.
*   **Качество:** Сбои в одном домене не влияют на другие. Полное соответствие регуляторам.
*   **Снижение затрат:** Команды работают параллельно без координационных издержек.
*   **Масштабирование:** Новые направления (фарма, оборудование) интегрируются как новые домены без влияния на ядро.

## Часть 3: Критические меры для качества сервисов

Для обеспечения бесперебойной и безопасной работы критичных систем в роадмап встроены специальные меры.

| **Направление** | **Критические меры** | **Этап внедрения** |
| :--- | :--- | :--- |
| **Медицинские сервисы** | - Шифрование данных в покое и при передаче<br>- Геораспределённое развёртывание<br>- Регулярное тестирование резервного копирования<br>- Централизованный аудит всех операций | Фаза 1 (базовая безопасность), Фаза 3 (изоляция домена), Фаза 4 (оптимизация) |
| **Финансовые сервисы** | - Соответствие стандарту PCI DSS<br>- Репликация данных в реальном времени<br>- Мониторинг подозрительных операций (антифрод)<br>- Полный аудит всех транзакций | Фаза 1 (базовая безопасность), Фаза 3 (изоляция домена), Фаза 4 (оптимизация) |
