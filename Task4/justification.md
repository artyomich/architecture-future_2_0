
# Обоснование конфигурации Terraform для "Будущее 2.0"

## 1. Обзор подхода

Данная конфигурация использует **декларативный подход Infrastructure as Code (IaC)** с помощью Terraform для автоматизации развёртывания базовой IaaS-инфраструктуры в Azure. Мы применяем **гибридный подход**: Terraform управляет IaaS-компонентами (VM, сеть, диски), тогда как сложные PaaS-сервисы (Kafka, Data Lake, DWH) развертываются отдельно. Это обеспечивает баланс между воспроизводимостью и сложностью на начальном этапе.

## 2. Выбор ресурсов и параметров

### 2.1. Сетевая инфраструктура
- **VPC с подсетями по доменам**: Обеспечивает строгую изоляцию между медицинским, финтех, ИИ и другими доменами на сетевом уровне, что критично для соответствия регуляторным требованиям (HIPAA, PCI DSS).
- **NAT Gateway только для подсети интеграции**: Минимизирует затраты. Другие домены работают во внутренней сети и не требуют исходящего интернет-трафика. Интеграционный домен нуждается в доступе к внешним API и управляемым сервисам Azure.

### 2.2. Вычислительные ресурсы (VM)
- **Размеры VM подобраны под нагрузку**:
    - `Standard_B2s` для Medical, Fintech, Portal, Gateway: Базовая нагрузка для API и веб-интерфейсов.
    - `Standard_D2s_v3` для AI и EventBus: Требуется больше памяти для ML-моделей и буферизации событий.
    - `Standard_D4s_v3` для ETL: Высокая CPU и память для эффективной обработки больших объёмов данных.
- **Ubuntu 22.04 LTS**: Стабильная, безопасная и поддерживаемая ОС с отличной поддержкой всех необходимых технологий (Docker, Python, Java).

### 2.3. Хранилище
- **Premium_LRS для всех дисков**: Гарантирует высокую производительность и низкую задержку для критичных приложений и баз данных.
- **Отдельные managed disks**: Позволяет независимо масштабировать и управлять хранилищем для каждого домена.

## 3. Декларативный подход

Использование декларативного подхода (вместо императивного) предоставляет ключевые преимущества:
1.  **Идемпотентность**: `terraform apply` всегда приводит инфраструктуру к описанному состоянию, независимо от её текущего состояния. Это исключает ошибки, связанные с ручным управлением.
2.  **Предсказуемость**: Команда `terraform plan` показывает все изменения **до** их применения, что позволяет избежать непредвиденных сбоев.
3.  **Документация как код**: Конфигурационные файлы сами являются актуальной и точной документацией текущей инфраструктуры.

## 4. Infrastructure as Code: Воспроизводимость и масштабируемость

### 4.1. Воспроизводимость
- **Проблема без IaC**: Разные окружения (dev, staging, prod) часто отличаются, что приводит к ошибкам типа "работает на моей машине". Восстановление после сбоев занимает дни.
- **Решение с IaC**: Один и тот же код Terraform создаёт идентичную инфраструктуру в любом окружении. Восстановление после полного сбоя занимает часы.

### 4.2. Масштабируемость
- **Проблема без IaC**: Добавление нового домена (например, фармацевтики) требует ручного копирования настроек, что медленно и подвержено ошибкам.
- **Решение с IaC**: Для добавления нового домена достаточно скопировать блоки ресурсов в `main.tf` и настроить переменные. Terraform автоматически создаст всю необходимую изолированную инфраструктуру, что сокращает время интеграции с месяцев до дней.
